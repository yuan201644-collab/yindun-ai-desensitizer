# 「隐盾」技术架构设计文档

## 一、总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                    用户入口 (零门槛)                           │
│          H5 网页端 ───── 微信小程序 (复赛)                      │
│              uni-app (Vue 3 + TypeScript)                   │
└──────────────────────────┬──────────────────────────────────┘
                           │
          ┌────────────────┴────────────────┐
          ▼                                 ▼
┌──────────────────┐            ┌──────────────────────┐
│  前端 Canvas 引擎 │  (本地)     │   FastAPI 后端 (GPU)  │ (精准增强)
│  · Tesseract.js  │◄──────────►│  · PaddleOCR GPU     │
│  · 像素化/模糊    │  可选切换    │  · YOLOv8-nano       │
│  · 不可逆替换     │            │  · 脱敏算法库         │
│  · 图片不离开设备  │            │  · 反还原检测引擎     │
└──────────────────┘            └──────────────────────┘
```

**核心设计理念：端侧优先 + 服务端增强 双模式**
- **本地模式**：OCR/Tesseract.js + Canvas 脱敏，图片完全不出设备
- **精准模式**：PaddleOCR GPU 精准识别 → 仅返回坐标 → 前端 Canvas 脱敏
- 两种模式一键切换，用户自主选择

## 二、四大模块架构设计

### 模块一：识别模块 (OCR + 目标检测)

| 项目 | 选型 | 说明 |
|------|------|------|
| 文本检测+识别 | **PaddleOCR** (ONNX 推理) | 中文识别准确率 > 95%，支持 GPU 加速 |
| 目标检测 | **YOLOv8-nano** | 最小 YOLO 模型 (6MB)，CPU 也可运行 |
| 本地 OCR | **Tesseract.js v5** (WASM) | 浏览器端运行，中文可用，隐私性最高 |

**实现逻辑：**
1. 图片解码 → 尺寸检查 → GPU 推理
2. PaddleOCR 返回 `[{bbox, text, confidence}]`
3. 正则引擎对 `text` 进行敏感信息分类（身份证/手机/地址等 10+ 类）
4. YOLO 并行检测人脸/证件/票据等实体
5. 组装 JSON 返回前端，图片内存立即释放

**扩展接口：** 在 `app/services/ocr_service.py` 中可替换 OCR 引擎；在 `app/core/config.py` 的 `SENSITIVE_PATTERNS` 字典中添加新模式。

---

### 模块二：脱敏算法模块

| 算法 | 原理 | 抗AI还原能力 | 使用场景 |
|------|------|-------------|---------|
| **像素化** | 降采样 + 随机微扰动 → 升采样 | ⭐⭐⭐ 良好 | 通用打码，观感友好 |
| **高斯噪点混淆** | 多轮高斯模糊 + 纹理感知噪点注入 | ⭐⭐⭐⭐ 强 | 高敏感区域 |
| **不可逆替换** ⭐ | 种子哈希驱动像素重排 + 伪随机值注入 | ⭐⭐⭐⭐⭐ 极强 | 核心创新，信息论不可逆 |
| **字符掩码** | 格式感知掩码 (如 `110****1234`) | N/A (文本) | 文本脱敏 |

**实现逻辑：**
1. 接收脱敏区域坐标 `{x, y, w, h}` + 算法名
2. `DesensitizerRegistry` 工厂模式调度对应算法
3. 算法仅处理 ROI 区域，不影响图片其余部分
4. 返回完整图片（numpy 数组）或 Base64

**扩展接口：** 在 `app/core/algorithms/` 下新增 `.py` 文件，继承 `BaseDesensitizer` 并注册到 `DesensitizerRegistry` 即可。

---

### 模块三：前端页面模块

| 页面 | 路由 | 功能 |
|------|------|------|
| **图片脱敏** | `/pages/index/index` | 上传 → OCR识别 → 选择区域 → 脱敏 → 下载 |
| **文本脱敏** | `/pages/text/index` | 粘贴文本 → 本地正则检测 → 高亮预览 → 掩码 → 复制 |
| **强度检测** ⭐ | `/pages/check/index` | 上传原图+脱敏图 → SSIM/PSNR/纹理熵评估 → 风险评分+建议 |

**技术选型：**
- **框架**：uni-app (Vue 3 Composition API + TypeScript)
- **样式**：UnoCSS (原子化 CSS，H5/小程序双端兼容)
- **Canvas 引擎**：自研 `canvas.ts` 工具库，三种算法纯前端实现
- **API 通信**：`uni.request` / `uni.uploadFile`（适配小程序）

**设计原则：**
- 三步完成核心操作（上传→处理→下载）
- 无需注册登录
- 暗色主题，传递隐私安全感

---

### 模块四：后端服务模块

| 端点 | 方法 | 功能 |
|------|------|------|
| `GET /health` | GET | 健康检查 + GPU 状态 |
| `POST /api/ocr` | POST | 上传图片 → 返回敏感区域坐标 |
| `POST /api/desensitize/image` | POST | 服务端脱敏（大文件备选） |
| `POST /api/desensitize/text` | POST | 文本脱敏 |
| `POST /api/check` | POST | ⭐ 脱敏强度安全性检测 |

**技术栈：**
- **Web 框架**：FastAPI (异步、自动 Swagger 文档)
- **GPU 推理**：PaddlePaddle-GPU + CUDA 11.8
- **图像处理**：OpenCV + Pillow
- **数学运算**：NumPy + SciPy + scikit-image
- **部署**：Docker (CUDA 镜像) + Uvicorn

**安全机制：**
- 图片仅内存处理，不落盘，响应后释放
- CORS 限制（生产环境）
- 文件大小/格式/尺寸三重校验
- 请求频率限制
- 日志不记录请求体（防隐私泄漏）

## 三、数据流设计

### 图片脱敏数据流
```
用户选择图片
  → 前端校验 (大小/格式/尺寸)
  → Canvas 渲染预览
  → [模式选择]
      ├─ 本地：Tesseract.js WASM OCR → 前端正则分类
      └─ 精准增强：上传 → PaddleOCR+YOLO → 返回 {regions}
  → 前端叠加半透明标注框 (用户可增删)
  → 用户选择脱敏算法 + 强度
  → Canvas 逐区域应用脱敏算法
  → 预览 → 下载 PNG
  → [可选] 上传到 /api/check 做强度检测
```

### 文本脱敏数据流
```
用户粘贴文本
  → 前端正则引擎扫描 (10+ 类敏感模式)
  → 高亮标注预览 (红/黄/橙 三色风险等级)
  → 用户确认 → 一键掩码
  → 预览脱敏结果 → 复制到剪贴板
  (全程本地，无网络请求)
```

## 四、技术亮点

1. **安全专业壁垒**：不可逆替换算法基于信息论设计，像素重排 + 种子哈希 + 多轮迭代，AI 超分模型无法重建原始梯度
2. **隐私架构设计**：端侧优先，敏感数据最小化上传，架构级隐私保障
3. **轻量化落地**：PaddleOCR ONNX + YOLO-nano 极小模型，CPU 也可运行
4. **模块化可插拔**：算法注册表模式、敏感模式字典配置，功能增删无需改核心代码
