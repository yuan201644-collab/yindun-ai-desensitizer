## 协作机制

### 开发流程
```
需求讨论 (全团队 1h/周)
  → A 编写接口规范 → B/C 并行开发
  → 每日 10min 站会同步进度
  → 每周五集成测试
```

### 代码协作
- **版本管理**：Git + GitHub (私有仓库)
- **分支策略**：`main` (稳定) + `dev` (开发) + `feature/xxx`
- **代码审查**：合并前至少一人 Review

### 接口约定
- B (前端) 和 C (后端) 在开发前对齐 API 接口文档
- 所有 API 响应格式统一：`{ success: bool, data?: any, error?: string }`
- 图片传输优先使用 `multipart/form-data` 上传

## 风险应对

| 风险 | 应对方案 |
|------|---------|
| 某位同学技能不足 | 各方向提供学习路径；A 作为组长可支援两端 |
| GPU 环境不可用 | 降级到 CPU 模式，PaddleOCR CPU 推理仍可用（慢但能跑） |
| 开学后时间紧张 | 初赛 MVP 集中在暑假完成，后续仅迭代 |
| 微信小程序审核 | 复赛阶段提前提交审核，预留 1 周 buffer |
