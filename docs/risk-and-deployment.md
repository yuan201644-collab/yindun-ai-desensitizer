# 「隐盾」风险分析、落地方案与电信场景适配

## 一、项目风险分析

### 1.1 技术风险

| 风险项 | 概率 | 影响 | 等级 | 应对策略 |
|--------|------|------|------|---------|
| **PaddleOCR 中文识别率不达预期** | 低 | 高 | 🟡 中 | 预设场景模板降低识别难度；用户可手动校正识别区域；持续收集 bad case 优化 |
| **GPU 环境不可用/不稳定** | 中 | 高 | 🟡 中 | 设计 CPU 降级方案；PaddleOCR CPU 模式可用（单图 3-5 秒）；前端 Tesseract.js 本地兜底 |
| **不可逆算法被新型 AI 模型突破** | 低 | 中 | 🟢 低 | 算法模块化设计，可独立升级；反还原检测引擎持续监控；多算法组合增强 |
| **小程序 Canvas 兼容性问题** | 中 | 中 | 🟡 中 | 提前在真机上测试；uni-app 封装了平台差异；备选纯 H5 方案 |
| **大图片处理性能瓶颈** | 中 | 低 | 🟢 低 | 前端自动缩放（最大 4096px）；后端异步处理；分块处理大图 |

## 二、落地方案

### 2.1 部署架构

```
┌──────────────────────────────────────────────────┐
│                     用户                           │
│         浏览器 (H5) / 微信小程序                    │
└──────────────┬───────────────────────────────────┘
               │
    ┌──────────┴──────────┐
    ▼                     ▼
┌──────────┐      ┌──────────────┐
│  Vercel  │      │ GPU Cloud    │
│  前端托管  │      │ 后端 API     │
│  (免费)   │      │ (按量付费)    │
│          │      │              │
│  · 静态   │      │  · FastAPI   │
│  · CDN    │      │  · PaddleOCR │
│  · HTTPS  │      │  · YOLOv8    │
└──────────┘      └──────────────┘
```

### 2.2 部署方案（按阶段）

| 阶段 | 方案 | 成本 |
|------|------|------|
| **开发阶段** | 本地开发机 + ngrok 内网穿透 | 免费 |
| **初赛演示** | Vercel(前端) + AutoDL GPU 实例(后端) | ~¥3/小时 |
| **复赛** | Vercel(前端) + 阿里云 GPU 实例(后端) | ~¥200/月 |
| **决赛/正式** | Vercel(前端) + 云 GPU Server | ~¥500/月 |

### 2.3 部署步骤

1. **前端部署 (Vercel)**：
   ```bash
   cd frontend && npm run build:h5
   # 连接 GitHub 仓库，Vercel 自动部署
   ```

2. **后端部署 (GPU 云服务器)**：
   ```bash
   # 使用 Docker
   docker build -t yindun-backend:gpu .
   docker run --gpus all -p 8000:8000 yindun-backend:gpu
   ```

3. **域名 + HTTPS**：
   - 前端：Vercel 自动提供 `*.vercel.app` 域名 + SSL
   - 后端：Nginx 反向代理 + Let's Encrypt

## 三、与电信运营商场景的深度适配

### 3.1 为什么选择电信？

- 南京邮电大学与电信运营商有天然的合作关系
- 惠民赛道的社会价值与运营商"服务大众"定位一致
- 运营商拥有海量用户触达能力（营业厅、App、公众号）

### 3.2 四大适配场景

#### 场景一：电信营业厅业务办理

**痛点**：客户办理业务需出示身份证、填写个人资料，纸质单据和电子截图存在隐私泄露风险。

**适配方案**：
- 营业厅自助终端集成「隐盾」脱敏功能
- 工作人员拍照录入客户证件后，系统自动脱敏
- 脱敏后的单据截图可安全转发、存档

**演示方式**：模拟营业厅场景，展示一张业务单从拍照 → 脱敏 → 存档的全流程。

#### 场景二：反诈公众号/小程序集成

**痛点**：电信反诈宣传需要工具让用户"看得见、用得上"。

**适配方案**：
- 「隐盾」作为功能模块嵌入电信反诈小程序
- 用户在使用反诈功能的同时，可以一键脱敏截图中的个人信息
- 配合"个人信息保护科普"内容，形成"宣传 + 工具"组合

**演示方式**：展示电信反诈小程序内调用「隐盾」脱敏功能。

#### 场景三：客服系统自动脱敏

**痛点**：电信客服处理用户问题时，屏幕可能显示用户身份证号、地址等敏感信息。

**适配方案**：
- 在客服工作台截图功能中集成自动脱敏
- 客服截屏分享问题时，敏感信息自动打码
- 降低内部信息泄露和合规风险

**演示方式**：模拟客服截图 → 自动脱敏 → 分享到内部群。

#### 场景四：套餐/账单截图分享

**痛点**：用户经常在社交平台分享套餐、账单截图，包含手机号等个人信息。

**适配方案**：
- 电信 App 内截图分享时，自动弹出脱敏提示
- 一键脱敏手机号 → 安全分享
- 作为用户权益保护功能宣传

### 3.3 对接路径

```
Step 1  技术联调：提供 API / SDK → 对接电信系统
Step 2  试点验证：选择 2-3 个营业厅试点
Step 3  效果评估：收集使用数据，优化产品
Step 4  规模推广：向更多营业厅/线上渠道推广
```

## 四、长期商业模式探索（决赛后）

| 模式 | 说明 | 收费逻辑 |
|------|------|---------|
| **C 端免费** | 个人用户永久免费 | 惠民属性，公益价值 |
| **B 端 SaaS** | 小微企业脱敏 API | 按调用量收费（低价） |
| **政企定制** | 运营商/政务场景定制 | 项目制合作 |
| **开源社区** | 核心算法开源 | 社区共建 + 企业版增值 |

决赛阶段暂不重点展示商业模式，聚焦社会价值和惠民属性。
